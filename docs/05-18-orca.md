The orca section configures the ORCA layer of a run. It selects the profile, the functional and basis set, the SCF and TDDFT controls, and the runtime that launches ORCA, and the framework reads it only when orca appears in the theory queue of &amp;CONTROL. The classic spelling of the section is &amp;ORCA; in YAML and agent JSON it is the orca mapping.

The profile is the unit of work. Each profile compiles to a chain of ORCA steps, from a ground-state single point (dft_energy) to an excited-state spin-orbit calculation (tddft_soc), and the jobtype is settled from the capability the profile reports to the framework. [Section 5](05-keyword-sections.html) describes how a jobtype reaches a profile.

The table lists the execution and program keys first, then the method and model keys, then the spectrum-output keys, and the framework-parity keys last.

The skill exposes the following profiles. A profile fixes the method and the set of properties a calculation returns.

Full descriptions for all available keywords are summarized below.

**execution_mode** - Selects the run arm. local writes a bash script and runs it in the calculation directory, and slurm writes a batch script and submits it with sbatch. The default is local.

**shell** - Prepends extra shell commands, such as module loads, to the run script. A list is joined one command per line and a string is split on semicolons; the commands run before ORCA starts. The default is empty.

**project** - Sets the file stem of the run. The input, the output and the point-charge side file are named &lt;project&gt;.inp, &lt;project&gt;.out and &lt;project&gt;.pc in the calculation directory; the default is orca_calc.

**profile** - Selects the ORCA profile, and with it the step chain, the method and the capability the skill reports. The 14 profiles split into six ground-state ones (dft_energy, dft_gradient, dft_dipole, dft_opt_min, dft_opt_ts, dft_frequency) and eight excited-state ones (tddft_energy, tddft_gradient, tddft_transition_dipole, tddft_nac, tddft_soc, tddft_opt_min, tddft_opt_ts, tddft_frequency). The profile must agree with method, and each one compiles to a fixed chain of ORCA steps, so the jobtype and the profile answer the same question; a name outside the list is refused at validation.

**orca_project** - Sets the project name in the framework spelling of the section, which is the spelling a converted or classic input writes. A non-empty value is copied onto project, so it wins over whatever project carries, and ORCA_PROJECT is exported with the result. All file names in the calculation directory follow it; the default is ORCA.

**orca_path** - Names the ORCA installation root. The run script exports it as ORCA, then prepends the MPI directories and starts $ORCA/orca on &lt;project&gt;.inp with the output redirected to &lt;project&gt;.out and stderr merged into the same log. A path that does not exist is refused at validation rather than failing remotely; the default is empty.

**mpi** - Names the MPI library directory of a parallel ORCA build. The run script prepends $MPI/lib to LD_LIBRARY_PATH and $MPI/bin to PATH so the launcher and its libraries resolve; the default is empty, which suits a serial ORCA build.

**orca_mem** - Sets the memory of one ORCA process in MB and is written as the %maxcore line of the deck. The budget is per process, not per job, so a run with nproc ranks asks the machine for nproc times this value. The default is 1000.

**orca_nproc** - Sets the number of ORCA processes and is written as nprocs in the %pal block of the deck. It is the framework spelling of the rank count; nproc is the spelling a standalone configuration writes, and the two fold to their larger value so neither can shrink a request made in the other. The default is 1.

**nproc** - Sets the process count written to the %pal block. It is the spelling a standalone configuration writes, while orca_nproc is what the framework forwards from &ORCA. The pair folds to its larger value once, and the folded count is what both the deck and the resource arithmetic use. The default is 1.

**thread** - Sets the thread count of one ORCA process. The slurm script passes it as #SBATCH --cpus-per-task, so the scheduler allocates that many cores per task, while a local run leaves the thread count to the machine it lands on. orca_thread is the framework spelling and the larger of the pair wins; the default is 1.

**orca_thread** - Sets the thread count in the framework spelling of the section. It is folded into thread once, and the larger of the two values is kept, so a request made through either spelling survives. The default is 1.

**keep_tmp** - Keeps the calculation directory after the run. 1 leaves the input, the output and the scratch files in place, and 0 removes the directory once the results are parsed; the default is 0.

**slurm_time** - Sets the batch time limit in HH:MM:SS and is written as #SBATCH --time; the default is 01:00:00.

**slurm_partition** - Sets the batch partition and is written as #SBATCH --partition; the default is default.

**slurm_ntasks** - Sets the number of batch tasks and is written as #SBATCH --ntasks; the default is 1. The ORCA process count is requested separately by nproc in the %pal block.

**slurm_memory** - Sets the memory of the batch allocation in MB and is written as #SBATCH --mem; the default is 4000. It is the budget of the whole job rather than of one ORCA process.

**slurm_command** - Names the submission command of a slurm run. The default is empty, which leaves the sbatch invocation to the runner, and a non-empty value is carried with the job settings.

**method** - Sets the electronic-structure method. dft covers the ground state: energy, analytical gradient, dipole, optimization and frequencies. tddft covers the excited states: excitation energies, transition dipoles, excited-state gradients, NACME, spin-orbit coupling and numerical frequencies. The method must match the profile prefix and must support the profile task, the legacy sf_tddft method is refused, and a tddft run whose ladder holds no excited state is refused rather than degraded to a ground-state run.

**functional** - Names the exchange-correlation functional written at the head of the ORCA keyword line, ahead of the basis set and the job keywords. The value is lowercase free text and is not checked against a list, so any functional the installed ORCA build knows is accepted and an unknown name is reported by ORCA itself. The default is pbe0.

**basis** - Sets the orbital basis set, written after the functional on the main keyword line. The accepted names are the minimal sto-3g, the Pople sets 3-21g, 6-31g, 6-31g\*, 6-31g\*\*, 6-311g, 6-311g\* and 6-311g\*\*, the Karlsruhe sets def2-svp, def2-tzvp, def2-tzvpp, def2-qzvp and def2-qzvpp, and the Dunning sets cc-pvdz, cc-pvtz, cc-pvqz, aug-cc-pvdz, aug-cc-pvtz and aug-cc-pvqz. The name is lowercased and stripped of spaces before the check, and the default is def2-svp.

**density_fitting** - Turns resolution-of-the-identity density fitting on or off. true appends RIJCOSX and then aux_basis to the keyword line, after the functional and the basis set. false omits both, which leaves a plain four-centre SCF. RIJCOSX is compatible with TDDFT gradients and numerical Hessians, so the default true is kept for every profile; the value must be a boolean.

**aux_basis** - Names the auxiliary basis set that RIJCOSX fits the Coulomb and exchange terms against. It is only written when density_fitting is true, and an empty value drops it while RIJCOSX stays. The name is free text, so it must be one the installation provides; the default is def2/J.

**dispersion_correction** - Sets the Grimme dispersion correction appended after the basis and density-fitting keywords: d3 becomes D3BJ, d3zero becomes D3ZERO and d4 becomes D4. An empty value or none writes no correction at all, and any other spelling is refused. The value is lowercased and stripped before the mapping, and the default is d3.

**grid_level** - Sets the integration grid of the SCF. 0 keeps the ORCA default and writes no extra line. 1, 2 and 3 write a second keyword line, ! DEFGRID1, ! DEFGRID2 or ! DEFGRID3, so the main keyword line keeps its usual layout. Any other integer is refused, and the default is 2.

**nstate** - Sets the number of electronic states in the ladder, ground state included. The value must be at least 1, must agree with the length of state_spin, and bounds target_states; the default is 1, a ground-state run.

**tddft_nroots** - Sets the root count of the %tddft block. Normalization derives it as the larger of the excited singlet and triplet counts, so the value is a result of the build rather than a hand setting; the default 0 becomes that derived count, and a tddft run that still has no excited state is refused.

**nsing_root** - Counts the excited singlet roots of the ladder. Normalization derives it from state_spin and it decides which target states go to irootlist; the default 0 means the value has not been derived yet.

**ntrip_root** - Counts the triplet roots of the ladder. Normalization derives it from state_spin and it offsets triplet targets into trootlist; the default 0 means the value has not been derived yet.

**tda** - Applies the Tamm-Dancoff approximation to the TDDFT response. true writes TDA true in the %tddft block and false leaves the ORCA default response; the default is false.

**num_freq** - Chooses the frequency keyword. On the ground state false writes AnFreq and true writes NumFreq. On the excited state the keyword is always NumFreq, because ORCA has no analytical TDDFT second derivatives, so the switch only controls the DFT frequency profiles. The value must be a boolean and the default is false; the .hess file is written by ORCA automatically and no %output Print[P_Hessian] block is requested.

**scf_converge** - Records the SCF convergence threshold. Every deck carries TightSCF on the keyword line, so the threshold the ORCA run applies comes from that keyword rather than from this value; the default is 1e-8.

**scf_maxit** - Limits the SCF iterations through MaxIter in the %scf block. The same block also asks for the MO coefficients with Print[P_MOs] 1; the default is 200.

**opt_converge** - Declares the optimization convergence request. The value is not written into the deck; the optimization is settled from the opt_converge value the skill returns once ORCA finishes, and the default false accepts a run that stopped early.

**opt_maxit** - Limits the optimization cycles through MaxIter in the %geom block. The block is written only for the optimization profiles; the default is 100.

**ir_width** - Sets the half-width of the Lorentzian broadening of the IR spectrum in cm^-1; the default is 100.0. This keyword is accepted but has no effect in v3.0.0.

**ir_scale** - Scales the intensities of the IR spectrum. The default is 1.0. This keyword is accepted but has no effect in v3.0.0.

**uv_width** - Sets the broadening width of the UV/visible spectrum in cm^-1; the default is 100.0. This keyword is accepted but has no effect in v3.0.0.

**nics_ring** - Lists the ring indices used for an NICS scan. The default [0] names no ring. This keyword is accepted but has no effect in v3.0.0.

**nics_scan** - Lists the scan distances of an NICS calculation in Angstrom. The default is [0.0]. This keyword is accepted but has no effect in v3.0.0.

**charges** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**multiplicity** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**ci** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**spin** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**coupling** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**target_states** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**temperature** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html). This keyword is accepted but has no effect in v3.0.0.

**solvent** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html). This keyword is accepted but has no effect in v3.0.0.

**verbose** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**shape** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html). This keyword is accepted but has no effect in v3.0.0.

**factor** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html). This keyword is accepted but has no effect in v3.0.0.

**scale** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html). This keyword is accepted but has no effect in v3.0.0.

The skill drives ORCA 5.0 or newer through the $ORCA/orca command and nothing else. Only the dft and tddft methods exist, the legacy sf_tddft method is refused, and the 14 profiles are the whole jobtype surface, so a jobtype without a matching profile is not offered.

The molecular restriction is absolute: a non-zero pbc is refused by both the framework capability gate and the skill validation, and cell, lattice_vector and kpoint are never read. Background point charges travel in a &lt;project&gt;.pc side file that the deck references through %pointcharges, because ORCA rejects inline rows, and NACME is not written at all for a run that carries point charges.

Excited-state limits follow ORCA. Nonadiabatic couplings are computed for S0-SN pairs only, a pair between two excited states is refused, and a SOC request needs a closed-shell singlet reference with excited singlet-triplet pairs. State spin labels must ascend in 2S and must agree with the declared pair maps, because ORCA orders the states that way and the skill refuses rather than reordering them.

Frequencies come from AnFreq or NumFreq on the ground state and from NumFreq on every TDDFT run; the dft_frequency profile deliberately carries no gradient step, because ORCA rejects EnGrad in a deck that also asks for a Hessian.
