The qdm section configures the qdm skill, which evaluates one-dimensional analytic nonadiabatic model Hamiltonians and propagates a fully quantum reference dynamics on them. The skill is pure Python and numpy, so the section names no program, no installation path and no input file. It is read when qdm appears in the theory queue of &CONTROL and is spelled &QDM in the classic input, qdm in YAML and agent JSON.

The geometry convention is the skill's own. Every model is one dimensional and is carried by a single dummy atom of symbol X, of which only the x component is read, so a structure is one line such as X -7.937658 0.0 0.0. The coordinate enters in Angstrom and is converted to Bohr internally, and y and z are ignored.

Full descriptions for all available keywords are summarized below.

**execution_mode** - Chooses the run arm. local evaluates the model in process with numpy; slurm serializes the configuration into the calculation directory, submits a blocking sbatch job, and collects {project}_results.json afterwards.

**project** - Sets the stem of the configuration, the reference output files and the results file, for example {project}_population.dat and {project}_norm.dat. The classic input spells the same value qdm_project, and the two are kept equal.

**qdm_project** - Sets the project stem through the classic-input spelling. It is copied into project, which names {project}_population.dat, {project}_norm.dat, {project}_grid.dat, {project}_density.npy and {project}_results.json.

**scratch_path** - Sets the parent directory of the calculation directory. An empty value places it under the run scratch root, and the directory is created when it does not exist.

**keep_tmp** - Keeps the calculation directory when 1, so the .dat dumps of energy, gradient, population and norm survive the call, and removes it once the results are collected when 0. The next step rebuilds the directory, so clearing cannot strand a stepped run.

**thread** - Sets OMP_NUM_THREADS for the process. The skill starts no MPI ranks, so threads are its only parallel axis; qdm_thread is the framework spelling and the larger value of a written pair wins.

**qdm_thread** - Sets the thread count through the framework spelling. It folds into thread, the larger value being used.

**slurm_time** - Sets the wall-clock limit of the submitted job in hh:mm:ss. It is read only when execution_mode is slurm.

**slurm_partition** - Sets the scheduler partition of the submitted job. An empty value writes no partition directive, so the cluster default answers.

**slurm_ntasks** - Sets the number of tasks of the submitted job. The skill starts no MPI ranks, so the value only describes the allocation.

**slurm_memory** - Sets the memory per node of the submitted job in MB.

**slurm_command** - Sets the submission command of the batch script, for example sbatch or a site wrapper. An empty value uses the default.

**profile** - Selects the model together with the output set. Every method carries four profiles, {method}_energy, {method}_gradient, {method}_nac and {method}_reference: the first three answer per-geometry properties, and _reference runs the split-operator propagation.

**method** - Selects the analytic model. tully1 maps the Tully 1990 example I, a single avoided crossing built from two exponential diabatic surfaces coupled by a Gaussian; tully2 maps example II, a flat surface crossed twice by a Gaussian barrier; tully3 maps example III, whose coupling grows and then plateaus so the nonadiabatic region stays extended on one side. lz1, lz2 and lz3 are the Landau-Zener linear-crossing models, in which two straight diabatic surfaces cross at the origin under a constant coupling; lz1 is the calibration target of the Zhu-Nakamura surface-hopping integrator because both premises of that reconstruction hold exactly there. The method has to match the profile, and every model carries two adiabatic states.

**model_mass** - Sets the wavepacket mass in atomic units, which is the mass the kinetic energy and the classical equations of motion use. The reference solver also forms its initial momentum as this mass times the first atom x velocity when velocities are present. The key is named model_mass because mass already means the framework atomic masses, and it is validated as positive. The standard Tully value is 2000 atomic units.

**tully_a** - Overrides the first Tully parameter, whose meaning follows the model: the asymptotic diabatic splitting A in Hartree for tully1, the Gaussian barrier height A in Hartree for tully2, and the constant diabatic splitting A in Hartree for tully3. A null value keeps the standard Tully 1990 parameter, which is 0.01, 0.1 and 0.0006 Hartree respectively. A written value must be positive, and a model that declares no such parameter ignores the key.

**tully_b** - Overrides the second Tully parameter: the wall steepness B in 1/Bohr for tully1, the barrier width B in 1/Bohr^2 for tully2, and the coupling strength B in Hartree for tully3. Null keeps the standard value of 1.6, 0.28 and 0.1 in those units. A written value must be positive.

**tully_c** - Overrides the third Tully parameter: the coupling strength C in Hartree for tully1 and tully2, and the coupling decay rate C in 1/Bohr for tully3. Null keeps the standard value of 0.005, 0.015 and 0.9 in those units. A written value must be positive.

**tully_d** - Overrides the fourth Tully parameter, the width D in 1/Bohr^2 of the Gaussian coupling, for tully1 and tully2. Null keeps the standard 1.0 and 0.06 1/Bohr^2. tully3 has no fourth parameter, so the key is silently ignored there rather than refused.

**tully_e** - Overrides the fifth Tully parameter, the asymptotic energy shift E in Hartree that raises the second diabatic surface of tully2. Null keeps the standard 0.05 Hartree. The two other Tully models declare no fifth parameter, so the key is ignored by them; lz_a and lz_b are ignored by all three Tully models for the same reason.

**lz_a** - Overrides the slope A in Hartree/Bohr of the two linear diabatic surfaces of the Landau-Zener models. The surfaces cross at the origin with slopes plus and minus A, so the adiabatic gap at the crossing is twice lz_b and the character-swap width scales as lz_b over lz_a. Null keeps the model class default of 0.04 Hartree/Bohr.

**lz_b** - Overrides the constant off-diagonal coupling B in Hartree of the Landau-Zener models, which is half the adiabatic gap at the crossing. Null keeps the model class default of 0.02 Hartree. A run that wants a narrower gap widens the swap region in proportion, and the calibration fixture pins a gap threshold that admits the hop evaluation.

**target_states** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**target_nac_pair** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**ref_ngrid** - Sets the number of grid points of the reference propagation, which has to be at least 2. Together with ref_xmin and ref_xmax it fixes the grid spacing, and the density snapshot of one save is an array of shape (ngrid, 2). The default 2048 matches the reference fixtures.

**ref_xmin** - Sets the lower edge in Bohr of the reference grid. A null value keeps the fixed default window that starts at -30 Bohr. The wavepacket start has to lie inside the window, so a model whose initial coordinate falls below the edge raises instead of propagating on a truncated grid.

**ref_xmax** - Sets the upper edge in Bohr of the reference grid. A null value keeps the default window that ends at +80 Bohr. It has to be above ref_xmin, otherwise validation refuses the pair; the asymmetric window reflects the direction a Tully wavepacket travels.

**ref_dt** - Sets the time step of the reference propagation in atomic units of time. The value must be positive, and 20 atomic units is the default the fixtures use. The products ref_dt times ref_nsteps is the total propagation time.

**ref_nsteps** - Sets the number of propagation steps of the reference run; the value must be at least 1 and the default is 500. The step count together with ref_dt gives the total propagation time, and ref_save_every decides how much of it is stored.

**ref_save_every** - Sets the stride at which density snapshots are stored; the value must be at least 1, and 1 stores every step. The written {project}_density.npy has one frame per save, and the population and norm files follow the same cadence.

**wavepacket_sigma** - Sets the width in Bohr of the initial Gaussian wavepacket. The value must be positive, and the default is 0.5.

**wavepacket_k0** - Sets the fallback initial momentum in 1/Bohr, used when the run carries no velocities. With velocities present the solver takes model_mass times the first atom x velocity instead.

**charges** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**multiplicity** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**ci** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**spin** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**coupling** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**pbc** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**cell** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**lattice_vector** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**kpoint** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

The skill evaluates analytic models and no electronic structure: there is no molecule to build and no basis, functional or SCF cycle to converge, so a run needs no external program. The geometry is one dummy atom X, only its x component is read, and y and z are ignored. At least one atom still has to be supplied, because the coordinate has to come from somewhere; the symbol itself is never looked up in an element table.

Two states and one dimension are the model rather than a setting. Every Hamiltonian is 2x2, so nstate is 2 and any other value raises, and pbc, cell, lattice_vector and kpoint carry no meaning here: a periodic request is refused outright instead of being silently ignored. The default periodicity of the section is therefore non-periodic on all three axes.

Surface hopping is not part of the skill. The framework MD workflow consumes the per-step energy, gradient and NAC of a {method}_nac profile and integrates the trajectory itself; the skill's own propagation is the split-operator reference, selected as {method}_reference when the skill drives the run. An optimize or surface_hopping jobtype has no profile here and is refused by name under a skill driver, so an iteration the models cannot serve is never answered by a single point.

The reference run is strict about its own settings: a wavepacket start outside the grid window raises, a lower grid edge that is not below the upper edge raises, and a non-positive model_mass, ref_dt, wavepacket_sigma, ref_ngrid below 2, or a step or stride count below 1 is refused. Negative or zero Tully parameters are refused in the same way when they are written.
