The read section names finished calculation artifacts and the labels to extract from them. A read run never starts an engine and writes no data artifact: it hands each path to the parser of the single theory skill bound to the run and returns the frames to its caller, and the run log is bypassed so the working directory is left untouched.

A read run binds exactly one theory skill, uses driver main, and has no reference skill and no multiscale partition. At least one path and at least one label are required, because a read that asks for nothing would return a dataset with no content.

The keywords, default values, and short descriptions are listed below.

| profile | '' | Names the skill profile the parser uses to read iterative artifacts such as an MD or an optimize trajectory. Empty derives the profile from the… |
| energy | true | Asks the parser for energies. At least one of the four label switches must be on. The default is true. |
| gradient | true | Asks the parser for gradients. The default is true. |
| nac | false | Asks the parser for nonadiabatic couplings. The default is false. |
| soc | false | Asks the parser for spin-orbit couplings. The default is false. |

Full descriptions for all available keywords are summarized below.

**path** - Names a calculation directory, a calculation output file, or a file that lists one path per line. A single file whose non-comment lines all resolve to existing paths is read as a path list, and its entries are anchored to the directory of the list file, so a portable list can carry relative paths. Every other entry is a calculation directory or an output file, whose parent directory and file stem locate the artifacts. A path that does not exist is reported with the entry that failed, and a run that asks for no path is refused.

**project** - Sets the file stem of the artifacts to read. Empty takes the unique artifact stem found in a directory, or the file stem when path names a file, and falls back to the directory basename. The default is empty.

**profile** - Names the skill profile the parser uses, which is how an iterative artifact such as an MD or an optimize trajectory is read: the profile says which frames and which channels the file holds. An empty value derives the profile from the labels the run asks for, so the common case needs no profile. The value is passed to the reading function of the skill, not to a backend object, because a machine holding only finished artifacts has no engine to install.

**energy** - Asks the parser for energies. At least one of the four label switches must be on. The default is true.

**gradient** - Asks the parser for gradients. The default is true.

**nac** - Asks the parser for nonadiabatic couplings. The default is false.

**soc** - Asks the parser for spin-orbit couplings. The default is false.

The extracted frames are returned to the caller, which owns the filtering, the statistics and the persistence. A label that the parser cannot find is reported as missing in that frame rather than invented.
