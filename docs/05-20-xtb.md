The xtb section configures the xTB layer of a run. It selects the profile and the tight-binding or force-field Hamiltonian, and the runtime that launches the xtb executable. The classic spelling of the section is &amp;XTB; in YAML and agent JSON it is the xtb mapping.

The eight profiles pair each Hamiltonian with an energy or an energy-plus-gradient step. GFN2-xTB, GFN1-xTB and GFN0-xTB serve the qm and qm2 roles of a composite, while GFN-FF serves the mm role and is the only member that accepts a periodic cell. [Section 5](05-keyword-sections.html) describes how a jobtype reaches a profile.

The table lists the execution and program keys first, then the method keys, and the framework-parity keys last.

The skill exposes the following profiles. A profile fixes the method and the set of properties a calculation returns.

| Profile | Capability | Method |
| :--- | :--- | :--- |
| gfn2_energy | energy | gfn2 |
| gfn2_gradient | gradient | gfn2 |
| gfn1_energy | energy | gfn1 |
| gfn1_gradient | gradient | gfn1 |
| gfn0_energy | energy | gfn0 |
| gfn0_gradient | gradient | gfn0 |
| gfn_ff_energy | energy | gfn_ff |
| gfn_ff_gradient | gradient | gfn_ff |

Full descriptions for all available keywords are summarized below.

**execution_mode** - Selects the run arm. local writes a bash script and runs it in the calculation directory, and slurm writes a batch script and submits it with sbatch. The default is local.

**shell** - Prepends extra shell commands, such as module loads, to the run script. A list is joined one command per line and a string is split on semicolons; the commands run before xtb starts. The default is empty.

**project** - Holds the run label of the configuration. File naming follows xtb_project, which is the authoritative spelling and is mirrored into project at parse time; the schema default is xtb_calc.

**profile** - Selects the xTB profile, and with it the Hamiltonian and the step chain. Each of the four methods has an energy profile and a gradient profile: gfn2_energy and gfn2_gradient, gfn1_energy and gfn1_gradient, gfn0_energy and gfn0_gradient, and gfn_ff_energy and gfn_ff_gradient. The energy profiles run xtb with the method flag alone, and the gradient profiles add --grad and parse the engrad file. The profile must agree with method, and the default is gfn2_energy.

**xtb_project** - Sets the file stem of the run and is exported as XTB_PROJECT. The geometry file is named &lt;project&gt;.xyz, or &lt;project&gt;.coord for a periodic GFN-FF run in Turbomole format; an optional user template &lt;project&gt;.inp in the launch directory is prepended to the generated input; the output, the engrad, the point-charge file and the GFN-FF topology follow the same stem. The default is XTB.

**xtb_path** - Locates the xTB executable and, when it can be identified, the installation root. A directory is read as the root and the run script executes $xtb_path/bin/xtb; any other path is used as the binary itself; an empty value falls back to xtb in PATH. When a root is known, the script also exports XTBHOME to it and XTBPATH to $XTBHOME/share/xtb, which is where the parameters live. The default is empty.

**xtb_mem** - Sets the stack size of one xTB process in MB and is exported as OMP_STACKSIZE, with KMP_STACKSIZE copied from it. The budget is a thread stack rather than a heap limit, so a large value is cheap and does not reserve memory the calculation does not touch. The default is 4000.

**thread** - Sets the OpenMP threads of the single xTB process through OMP_NUM_THREADS. xTB starts no MPI ranks, so this is the only parallel axis the skill has; xtb_thread is the framework spelling and the larger of the pair wins. The default is 1.

**xtb_thread** - Sets the thread count in the framework spelling of the section. It is folded into thread once and the larger value is kept, so a request made in either spelling survives. The default is 1.

**keep_tmp** - Keeps the calculation directory after the run. 1 leaves the geometry, the input, the output and the engrad in place, and 0 removes the directory once the results are parsed; the default is 0.

**slurm_time** - Sets the batch time limit in HH:MM:SS and is written as #SBATCH --time; the default is 01:00:00.

**slurm_partition** - Sets the batch partition and is written as #SBATCH --partition; the default is default.

**slurm_ntasks** - Sets the number of batch tasks and is written as #SBATCH --ntasks; the default is 1. xTB starts no MPI ranks, so a larger count requests resources the calculation cannot use.

**slurm_memory** - Sets the memory of the batch allocation in MB and is written as #SBATCH --mem; the default is 4000.

**slurm_command** - Names the submission command of a slurm run. The default is empty, which leaves the sbatch invocation to the runner, and a non-empty value is carried with the job settings.

**method** - Selects the Hamiltonian written on the xTB command line: --gfn 2 for GFN2-xTB, --gfn 1 for GFN1-xTB, --gfn 0 for GFN0-xTB and --gfnff for GFN-FF. GFN2 and GFN1 are the two full parameterizations and answer energies and analytical gradients, while GFN0 keeps the EEQ charge model only, so it is not a full GFN Hamiltonian. GFN-FF is the force field member: it is the only method that writes a periodic cell, and it is the method that serves the mm role of a composite. The method must agree with the profile prefix, and the default is gfn2.

**stress** - Requests the whole-system stress tensor. It is meaningful only for a periodic gfn_ff run, where xTB writes the lattice gradient and the S0 block is filled in Hartree/Bohr^3; every other run returns a zero tensor. The default is false.

**keep_topology** - Reuses the GFN-FF topology that the previous evaluation left in the fixed calculation directory, so this geometry is scored on that bond list. The framework sets it for a dynamics run, whose surface must not change under the trajectory, and leaves it false for a search, where each trial geometry is scored with its own topology; a stale gfnff_topo is removed otherwise. The default is false.

**nstate** - Sets the number of electronic states. Normalization forces the value to 1, because xTB computes the ground state only and no excited surface exists; the default is 1.

**charges** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**multiplicity** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**ci** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**spin** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**coupling** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**verbose** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**solvent** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html). This keyword is accepted but has no effect in v3.0.0.

**temperature** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html). This keyword is accepted but has no effect in v3.0.0.

**shape** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html). This keyword is accepted but has no effect in v3.0.0.

**factor** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html). This keyword is accepted but has no effect in v3.0.0.

**scale** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html). This keyword is accepted but has no effect in v3.0.0.

**pbc** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html). The three flags are the periodic axes, and any non-zero flag selects the periodic arm: a cell is written and the geometry goes to a Turbomole coord file with $periodic 3. Only gfn_ff accepts it, and point-charge embedding is refused alongside it.

**cell** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**lattice_vector** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

**kpoint** - Framework keyword; the skill receives it from &MOLECULE and &MD. See [Section 5.2](05-02-system-molecule.html).

The skill wraps the xTB 6.x executable and is a ground-state engine: the capabilities are energy, gradient and stress, and there are no excited states, no NAC, no SOC and no Hessian or frequency profile. Energies and gradients come back from &lt;project&gt;.engrad in Hartree and Hartree/Bohr, and a parse failure points at &lt;project&gt;.out.

GFN-FF is the only periodic method. A non-zero pbc is refused for gfn2, gfn1 and gfn0, and point-charge embedding cannot be combined with periodic boundaries at all. Only a periodic GFN-FF run fills the stress tensor, from the lattice gradient, and only its S0 block.

Parallelism has one axis. xTB starts no MPI ranks, so thread (or xtb_thread) and the stack size set through xtb_mem are the whole resource story, and a user template &lt;project&gt;.inp in the launch directory is prepended to the generated input, which is how extra xTB keywords such as a solvent model are supplied.
