Most input mistakes are refused at validation, before any engine is started. This appendix collects those refusals by area, so that a run which stops at input can be diagnosed without reading the validator. The third column quotes the sentence the refusal opens with, shortened where the message names a list of options, and the section column points at the prose that explains the rule. The matrix is a map of the rules, not a substitute for them: a rule whose explanation matters is in the section named beside it.

| Area | Refused combination | Reason or message |
| :--- | :--- | :--- |
| jobtype | A basic token together with an advanced token, as in energy md, or two advanced tokens, as in train adaptive | Basic options are freely composable and advanced options must be used alone, so either combination is refused with both vocabularies printed ([Section 5.1](05-01-control.html)). |
| jobtype | The retired tokens hop and hybrid | Both tokens have been removed, and the message names the replacement: surface hopping is md with sfhp, and a hybrid is a composite run ([Section 5.1](05-01-control.html)). |
| jobtype | A token that is not in either vocabulary | Unknown jobtype, with the basic and advanced vocabularies printed in the message ([Section 6.1](06-workflows.html#61-job-types-and-workflow-resolution)). |
| theory | A label that is not a registered skill | The unknown label is refused at validation, so a typo fails at input rather than at the first dispatch ([Section 5.1](05-01-control.html)). |
| reference | nn in the reference queue, or more than three layers, or a layered theory with more than one reference layer outside adaptive sampling | The reference labels structures and cannot be a network; the layer count is bounded, and a layered theory accepts one reference layer unless the jobtype is adaptive ([Section 5.1](05-01-control.html)). |
| multiscale_type | A value other than qmmm or oniom, or qmmm with three theory entries | The key names a two-entry scheme only; three theory entries are always ONIOM3 ([Section 7](07-multiscale-calculations.html)). |
| multiscale_type | qmmm with a control.reference queue that is not an adaptive reference | The two providers come from control.theory; control.reference must be empty ([Section 7.1](07-multiscale-calculations.html#71-additive-qmmm)). |
| multiscale_type | A legacy qmmm_key declaration | qmmm_key is retired as a QMMM declaration; write multiscale_type qmmm with two theory methods and molecule.highlevel ([Section 7.5](07-multiscale-calculations.html#75-limitations)). |
| QMMM | No highlevel, or a highlevel that covers every atom | QMMM needs a proper QM region and a non-empty classical region ([Section 7.1](07-multiscale-calculations.html#71-additive-qmmm)). |
| QMMM | A q_qm set whose length is not the QM set, q_qm with several centers, or sc_charge with one center or without embedding | The charge order is the whole QM set in global order; a pinned set answers for one center only, and the charge iteration needs a field and a second center ([Section 7.4](07-multiscale-calculations.html#74-embedding-charges-and-self-consistency)). |
| embedding | ONIOM2 with a classical outer method and embedding true | Not supported; the message sends the run to multiscale_type qmmm, where the QM calculation receives the MM field ([Section 7.2](07-multiscale-calculations.html#72-oniom2-and-oniom3)). |
| embedding | ONIOM2 with several centers and read_charge, or read_charge together with external_charges | One static charge file has no single binding for per-center environments, and two background-field declarations are one too many ([Section 7.4](07-multiscale-calculations.html#74-embedding-charges-and-self-consistency)). |
| PBC | Mixed pbc flags, or a molecular backend as the whole-system layer | Partial periodicity is not supported; the outermost layer must carry the box, and a molecular backend is allowed only as a center region ([Section 8.4](08-periodic-systems.html#84-which-engines-support-pbc)). |
| PBC | A soft wall in a periodic system | A soft wall is a spring toward one point and has no shell to check against a cell face; keep the hard law or run without periodicity ([Section 5.13](05-13-constraint.html)). |
| md | nve with a thermostat, nvt without one, npt without a barostat or thermostat, or dissipate on an nve run | Each ensemble states which components it owns; the message names the ensemble that would accept the keyword ([Section 8.3](08-periodic-systems.html#83-dynamics-under-pbc)). |
| md | A barostat paired with a thermostat its derivation does not accept, or scr in the anisotropic cell mode | Parrinello-Rahman and MTTK are extended-Lagrangian schemes with a defined pairing; scr shears a liquid and supports the isotropic cell only ([Section 8.3](08-periodic-systems.html#83-dynamics-under-pbc)). |
| adaptive | dynsample, refine or transfer set to a non-zero value | The keyword is not ported in this adaptive build and must be 0 ([Section 10.5](10-machine-learning-potentials.html#105-adaptive-sampling)). |
| adaptive | load other than 1, zero sample_energy or sample_grad, a maximum threshold below its minimum, or an unknown analysis scope | A round starts from the supplied network, trains on energy and gradient, and its screens are ordered ([Section 10.5](10-machine-learning-potentials.html#105-adaptive-sampling)). |
| hessian | hess_driver main with hess_mode analytic or auto, or hess_driver skill on a backend without a frequency capability | The framework has no analytical second derivative; main is the displacement batch, and a skill driver needs a backend that produces the matrix ([Section 6.6](06-workflows.html#66-hessian-frequencies-and-thermochemistry)). |
| driver | A non-main driver with more than one theory skill, a driver name that is not the first skill, or a non-main driver with a path method or optimize_cell | A skill owns the whole iteration, so exactly one skill can own it; a variable-cell search is a framework loop ([Section 5.1](05-01-control.html)). |
| optimize | opt_pressure or opt_cell_coupling without optimize_cell | With the box held there is no lattice derivative for a pressure to act on ([Section 5.4](05-04-optimize.html)). |
| optimize | A hypersphere, IRC or band key on a method that cannot read it, a band without both endpoints, or irc_mode molden without a mode file | Each path keyword answers a question exactly one walk asks, and a walk without its endpoints or its imaginary mode has nothing to start from ([Section 6.4](06-workflows.html#64-reaction-paths-mep-irc-neb)). |
| search | sort_stat or sort_order outside its vocabulary | A misspelled statistic is not allowed to fall back to the default, because the default answers a different question ([Section 10.4](10-machine-learning-potentials.html#104-hyperparameter-search)). |
| read | path, project or profile without jobtype read, a read run without a path, a read run that asks for no label, or a read run with a non-main driver | Extraction never starts an engine: it needs one theory, no reference, the framework driver and at least one requested label ([Section 6.7](06-workflows.html#67-reading-finished-calculations)). |
| constraint | A retired flat restraint key, a ramp that drives a positive parameter to zero, endpoints shaped unlike the value they replace, or an inside or outside bias region | A restraint that arrives nowhere is worse than a refusal, so the old spellings name their block; the ramp and region rules are stated with the block ([Section 9.4](09-constraints.html#94-refused-combinations)). |

Two refusals are worth separating from the list because they are capability limits rather than vocabulary errors. A molecular backend cannot carry a periodic box, and a stress-driven barostat needs a backend that returns a stress tensor; both are refused where the plan is built, with a message naming the layer that must change. A run that reaches an engine and fails there is a different class of problem, and Section G covers it.

Warnings are not refusals. An ONIOM2 run with a classical outer method and embedding off is accepted with a warning that the same additive surface is spelled qmmm, because the calculation is well defined even though the spelling is not the recommended one. A skipped capability gate, which happens when skill discovery fails during a partial installation, is also a warning; it is printed so that a periodic run does not silently proceed on a backend nothing checked.
